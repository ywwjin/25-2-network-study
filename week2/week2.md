    - 브라우저 등의 에플리케이션은 프로토콜 스택에 의뢰해서 파이프를 연결하거나 데이터를 쏟아붓는다.

1. 소켓의 작성 단계
    - 클라이언트측 소켓을 만드는 법
        
        ![image.png](%EB%84%A4%ED%8A%B8%EC%9B%8C%ED%81%AC%20week2%20275ac05e6bdb80e3a770e01a4ccb683e/image%201.png)
        
        - 소켓 라이브러리의 socket이라는 프로그램 부품 호출 > socket 내부에 제어가 넘어가서 소켓을 만드는 동작 실행
        - 소켓이 생기면 디스크립터가 돌아오므로 애플리케이션은 이것을 받아 메모리에 기록(소켓을 식별할 수 있다)
    - 소켓을 만든 후 동작을 실행할 때 이때 디스크립터를 이용하면 프로토콜 스택이 빠르게 판단할 수 있음
    - DNS 서버에 조회를 보낼 때와 같이 Socket 라이브러리의 프로그램 부품을 호출하는 것이 요점
1. 파이프를 연결하는 접속 단계
    - 만든 소켓을 서버측의 소켓에 접속하도록 프로토콜 스택에 의뢰
    - 애플리케이션은 Socket 라이브러리의 connect라는 프로그램 부품을 호출하여 이 의뢰 동작 실행
    - 지정하는 디스크립터
        - 최초의 디스크립터는 소켓을 만들 때 돌아온 디스크립터
        - 지정한 디스크립터는 connect가 프로토콜 스택에 통지
        - 프로토콜 스택이 통지받은 디스크립터를 보고 어느 소켓을 서버측의 소켓에 접속할지 판단하여 접속 동작을 실행
    - 서버의 IP 주소
        - DNS 서버에 조회하여 조사한 액세스 대상 서버의 IP주소
        - 데이터 송,수신 동작을 실행할 때 송,수신 상태의 IP주소를 프로토콜 스택에 알려야 함
        - IP주소: 네트워크에 존재하는 각 컴퓨터를 식별하기 위해 각각에 서로 다른 값을 할당한 것(네트워크의 어느 컴퓨터인가 까지만 지정)
    - 포트 번호
        - IP번호가 어느 컴퓨터인지를 지정한다면 포트 번호로 어느 소켓에 접속할지를 지정
        - 디스크립터는 컴퓨터 한 대에서 소켓 식별을 위해 사용
            - 서버측 소켓의 디스크립터를 클라이언트에서는 알 수 없다
        - 포트 번호는 접속 상대(클라이언트>서버) 측에서 소켓을 식별하기 위해 사용
        - 서버>클라이언트의 소켓 포트 번호는 소켓을 만들 때 프로토콜 스택이 할당하고, 이 값을 접속 동작 시에 서버측에 통지
2. 메시지를 주고받는 송,수신 단계
    - 소켓에서 데이터를 쏟아 부으면 상대측의 소켓에 데이터 도착
    - 애플리케이션이 Socket 라이브러리를 통해 write 사용
        - 애플리케이션이 송신 데이터를 메모리에 준비
        - 송신 데이터: 사용자가 입력한 URL을 바탕으로 만든 HTTP의 리퀘스트 메세지
        - write를 호출할 때 디스크립터와 송신 데이터 지정
        - 프로토콜 스택이 송신 데이터를 서버에게 송신
        - 소켓에는 연결된 상대가 기록되어 있으므로 디스크립터로 소켓을 지정하면 연결된 상대가 판명되어 그곳을 향해 데이터 송신
        - 송신데이터는 네트워크를 통해 전부 그대로 액세스 대상의 서버에 도착
        - 서버는 수신 동작을 실행하여 받은 데이터의 내용을 조사, 적절한 처리 실행하여 응답 메시지 반송
3. 연결 끊기 단계에서 송,수신이 종료된다
    - Socket 라이브러리의 close 라는 프로그램 부품을 호출하여 연결 끝기 단계로 들어가도록 의뢰한다.
        - 웹서버측에서 close를 호출하여 연결을 끊는다
        - 클라이언트측에 전달되어 클라이언트의 소켓은 연결 끊기 단계로 들어간다
        - 브라우저가 read로 수신 동작을 의뢰했을 때 수신 데이터를 건네주는 대신 연결이 끊겼다는 사실을 브라우저에 통지
        - 브라우저에서도 close를 호출하여 연결 끊기 단계에 들어감

# **2. TCP/IP의 데이터를 전기 신호로 만들어 보낸다**

## (1) 소켓을 작성한다

### 1. 프로토콜 스택의 내부 구성

- 프로토콜 스택과 LAN 어댑터가 브라우저에서 받은 메시지를 서버에 송출하는 동작 탐험
    - 프로토콜 스택: OS에 내장된 네트워크 제어용 소프트웨어
    - LAN 어댑터: 네트워크용 하드웨어

![image.png](%EB%84%A4%ED%8A%B8%EC%9B%8C%ED%81%AC%20week2%20275ac05e6bdb80e3a770e01a4ccb683e/image%202.png)

- 네트워크 어플리케이션
    - 브라우저, 메일러, 웹 서버 등의 프로그램에 여기에 해당
    - 여기서부터 아래로 향하여 데이터 송,수신 등의 일을 의뢰
    - 어플리케이션의 아랫부분에는 socket 라이브러리, 그 안에는 리졸버가 내장(DNS 서버 조회)
- 프로토콜 스택(OS의 내부)
    - TCP, UDP는 모두 데이터 송,수신 프로토콜
        - 일반적인 애플리케이션은 TCP를 사용
        - DNS 서버 조회 등에서 짧은 제어용 데이터는 UDP를 사용
    - IP 프로토콜을 사용하여 패킷 송,수신 동작을 제어
        - 패킷: 데이터를 작게 나누어 패킷이라는 형태로 운반
        - 패킷을 통신 상대까지 운반하는 것이 IP의 주 역할
        - IP에는 ICMP, ARP 프로토콜을 다루는 부분이 포함
            - ICMP: 패킷을 운반할 때 발생하는 오류 통지, 제어용 메시지 통지
            - ARP: IP주소에 대응하는 이더넷의 MAC 주소를 조사할 때 사용
- LAN 드라이버
    - LAN 어댑터의 하드웨어 제어
- LAN 어댑터: 케이블에 대해 신호를 송,수신하는 동작 실행

### 2. 소켓의 실체는 통신 제어용 제어 정보

- 프로토콜 스택은 내부에 제어 정보를 기록하는 메모리 영역을 가지고 있으며, 통신 동작을 제어하기 위한 제어 정보 기록
- 프로토콜 스택은 제어 정보를 참조하면서 동작
    - 데이터 송신: 소켓에 기록되어 있는 상대의 IP주소나 포트 번호를 보고 그것을 대상으로 데이터 송신

    - 송신 뒤에 시간을 측정해야 하기 때문에 소켓에는 응답 여부와 동작 후 경과 시간 등이 기록되어 있음

## (2) 서버에 접속한다

### 1. 접속의 의미

- 소캣을 만들면 애플리케이션은 connect를 호출하고, 프로토콜 스택은 자기쪽 소켓을 서버측 소켓에 접속
- 클라이언트측, 서버측에 동작 개시를 전달하는 것도 접속 동작의 역할 중 하나
    - 클라이언트에서 IP 주소,포트 번호를 서버측에 전달, 서버측의 프로토콜 스택도 클라이언트의 정보를 가질 수 있다
- 버퍼 메모리: 송,수신하는 데이터를 일시적으로 저장하는 메모리 영역

### 2. 맨 앞부분에 제어 정보를 기록한 헤더를 배치한다

- 클라이언트와 서버가 연락을 절충하기 위한 제어 정보
    
    ![image.png](%EB%84%A4%ED%8A%B8%EC%9B%8C%ED%81%AC%20week2%20275ac05e6bdb80e3a770e01a4ccb683e/image%205.png)
    
    - 통신 동작 전체에서 어떤 정보가 필요한지 검토, 내용을 TCP 프로토콜의 사양으로 규정
    - 클라이언트와 서버가 대화할 때마다 제어정보를 부가한다
    - 접속 동작의 단계에서는 제어정보만으로 이루어짐
- 소켓에 기록하여 프로토콜 스택의 동작을 제어하기 위한 정보
    - 애플리케이션에서 통지된 정보, 통신 상대로부터 받은 정보가 수시로 기록되고, 프로토콜 스택은 차례로 정보를 참조하면서 움직임
    - 소켓의 제어 정보는 프로토콜 스택의 프로그램과 일체화
    - 소켓에 기록한 제어 정보는 상태측에서 볼 수 없다(헤더로 통신하기 때문)

### 3. 접속 동작의 실체

- 애플리케이션이 Socket 라이브러리의 connect를 호출
    
    ![image.png](%EB%84%A4%ED%8A%B8%EC%9B%8C%ED%81%AC%20week2%20275ac05e6bdb80e3a770e01a4ccb683e/image%206.png)
    
    - 서버측의 IP주소와 포트 번호를 쓰면 명령이 프로토콜 스택의 TCP 담당 부분에 전달
    - TCP 담당 부분은 서버의 TCP 담당 부분과의 사이에 제어 정보를 주고받는다
- 데이터 송,수신 동작의 개시를 나타내는 제어 정보를 기록한 헤더
    - 송신처와 수신처의 포트 번호가 가장 중요
    - 포트 번호를 통해 접속해야 하는 소켓을 지정하고 컨트롤 비트인 SYN 비트를 1로 만듦
- TCP 헤더를 IP 담당 부분에 건네주어 송신하도록 의뢰
    - IP 담당 부분이 패킷 송신 동작 실행, 네트워크를 통해 패킷이 서버에 도착하면 서버측의 IP담당 부분이 이것을 TCP 담당 부분에 건넨다
    - 서버측의 TCP 담당 부분이 TCP 헤더를 조사하여 포트 번호에 해당하는 소켓을 찾아낸다
    - 해당하는 소켓이 발견되면 필요한 정보를 기록, 접속 동작이 진행중이라는 상태가 됨
    - 서버의 TCP 담당 부분은 응답을 돌려보냄
- 서버 TCP 헤더 만듦
    - 클라이언트와 마찬가지로 TCP 헤더를 만든다
    - 응답을 돌려보낼 때 ACK 컨트롤 비트(패킷을 받았음)를 1로 만든다
    - TCP 헤더를 IP 담당 부분에 건네주어 클라이언트에 반송하도록 의뢰
- 패킷이 클라이언트에 도착
    - TCP 헤더에서 SYN이 1이면 접속 성공이므로, 소켓에 서버의 IP주소나 포트 번호 등과 함께 소켓이 접속 완료를 나타내는 제어 정보 기록
    - 패킷이 도착한 것을 서버에 알리기 위해 ACK 비트를 1로 만든 TCP 헤더를 반송
